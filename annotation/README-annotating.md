# Annotation desk — human judgement only

Emmanuel writes all obligation, deadline, role, escalation, rationale, difficulty and gold judgements. Nothing in the workspace is a suggested answer. The workspace shows CUAD's expert-labelled spans verbatim and flags label co-occurrence as a candidate only; co-occurrence does not establish conflict. Check the source contract and context before any judgement.

## Before cases
1. Complete every `include` field in `guide/obligation_types.yaml`; complete the remaining fields for every included category. Write and version `guide/annotation-guide.md`. Freeze the guide at `guide-v1.0` before any live run.
2. Run `python scripts/build_corpus.py --cuad-dir DIR --n 40` and `python scripts/make_annotation_workspace.py`. Open the generated files locally. Project-defined title buckets are not official CUAD families.
3. Use `config/splits.yaml` to plan the class and split counts. Aim for distinct source contracts between dev and test; the validator reports any overlap. A mutation counts under its original source. Test source files and compiled test gold remain private and must never be pushed before a valid completed live test run.

## Case files
Write YAML under `cases/src/`, one case per file or an array of cases. Use filenames beginning `test-` for held-out files and `dev-` for development files. Each case has `id`, `split`, `document_id`, `intake_party`, optional `business_context`, `class`, `gold_obligations`, `gold_should_escalate`, `gold_escalation_codes`, `rationale`, and `difficulty`. A mutated case also carries its `source_document_id`. An exact duplicate carries `duplicate_of`, identifying an earlier case in the same execution, with identical request content.

Each obligation is authored by you and contains your chosen `type`, `owed_by`, `clause_category`, `deadline`, and `clause_ref` with exact `category`, `char_start`, `char_end`. The deadline has `kind`; an absolute deadline requires an ISO `resolved_date`; other kinds carry whatever anchor, offset, rule, and date you judge supported. Gold `owed_by` uses `provider`, `customer`, `both`, or `unclear`; map licensor to provider and licensee to customer. Intake party retains its wider enum. For a conflicting case, supply at least two distinct exact refs in `conflict_clause_refs` (or in the obligation refs); the human determines whether the cited clauses genuinely conflict.

The six adversarial mechanisms are generated by `scripts/make_adversarial.py`; inspect `--help`. Mutations are logged, and altered/overlapping source labels are dropped. Non-English text requires a supplied excerpt or an explicitly selected translation adapter; no hidden network request occurs.

## Compile and validate
Run `python scripts/build_cases.py`, then `python scripts/validate_cases.py --strict`. Fix any reported issue yourself before committing the frozen hash. A successful validation says nothing about whether your legal or operational judgements are correct. Before publishing the commitment, review source-document overlap and the configured class distribution. `cases/FROZEN.sha256` commits to the compiled held-out file; it is the only held-out artifact pushed before the completed valid live run. Never show held-out gold or per-case test results to the build agent before freeze.

For a non-English mutation, put a single UTF-8 excerpt in `corpus/adversarial/source/` or pass `--non-english-file`. If no excerpt is supplied, the default adapter attempts offline English-to-Spanish translation of the explicit `--start`/`--end` source span. This requires the optional `requirements-translation.txt` dependency and a separately installed Argos language model; installing either is an explicit operator action, never an automatic network call. An explicit `--translator module:function` may replace it. The translated document has no CUAD labels; no gold obligations can be validated against unlabelled translated text as if they were original CUAD spans.
