## Local setup and verification

Use Python 3.11. On the embedding host, `make setup` creates `.venv` and installs `requirements.txt`; `make test` uses the venv with `B2_OFFLINE=1`. Direct requirements are pinned; transitive dependencies are not locked. Windows is not tested here. For migration only, deliberately install `python -m pip install -r requirements-export.txt`; Chroma is not a runtime or CI requirement. For new embeddings, the separate `requirements-embedding.txt` installs the local sentence-transformer stack; use a locally available, verified model directory via `B2_EMBEDDING_MODEL_PATH`.

On the Phase B machine, before modifying the source Chroma store:

1. Ensure the old Chroma manifest and the local `corpus/embeddings/chroma/` are present and refer to the same all-MiniLM model. The exporter copies the store before opening it, validates the legacy manifest's model/count/content digest, checks every stored chunk's text against its source document slice, and expects exactly 14,903 chunks by default.
2. Run `B2_OFFLINE=1 python scripts/export_lean_index.py`. On PowerShell set `$env:B2_OFFLINE='1'` first. The output is a text-free `chunks.json`, `vectors.npy`, manifest, retained legacy manifest and aggregate migration report; Chroma remains local/ignored. Default float16 storage uses float32 cosine comparisons. `--dtype float32` is available for a fresh export but may exceed the desired size; do not switch precision by reusing a quantized index. Inspect the aggregate size and the old-L2/new-cosine top-8 overlap for 200 deterministic stored-vector **self queries** in `migration_report.json`; it is a diagnostic, not a real-query benchmark. Float16 can change rankings near ties.
3. Run the independent full-store check (POSIX): `B2_OFFLINE=1 B2_BASE_ROOT="$PWD" B2_CHROMA_STORE="$PWD/corpus/embeddings/chroma" python -m pytest -q tests/test_v11.py::test_local_chroma_all_14903_slices`. In PowerShell set the three environment variables and run the same pytest target. It checks all 14,903 source slices and exported metadata. This check **was not run here** because the real store is only on OpenCode's host. The exporter also checks every slice during export. Do not treat the synthetic smoke test as that verification.
4. The Phase B Chroma store indexes the original 40 contracts, not the already committed dev mutation or future dev composites. After confirming model weights/provenance, run `B2_OFFLINE=1 python scripts/build_embeddings.py --split dev`; it reuses unchanged exported vectors and locally embeds missing/changed base documents. Re-run after dev composites are created. It updates `config/model.yaml`'s base `corpus_version`; commit the text-free base index and that version before freezing. Runtime refuses a selected non-duplicate document absent from its index. Verify the final size again.

The Phase B report records a locally obtained weights file; its hash must still be checked against the original Hugging Face weights before any real embedding or live run. The exporter proves agreement with the legacy manifest, not that external model provenance. No model download or network fallback is automatic in offline mode. Rebuild/re-export if model weights, source documents, labels, chunking, vectors or dtype change. The base version hashes length-framed base document bytes, DB document/label data, base provenance, text-free chunk metadata, vector-file bytes, and format/model/dimensions/dtype/chunking parameters. ## Local-only test synthetics and freeze

- `python scripts/make_composite.py --split dev SOURCE_A SOURCE_B` creates an ordered composite from two distinct real base documents. `--split test` writes the analogous test composite only to `corpus/synthetic_test/documents/`, its local manifest, and `db/test_docs.sqlite`. The composite is a whole-document join, not an adjudication or a claim that the sources originally formed one contract. The manifest records ordered source hashes, boundaries, separator and output hash; source offsets map into the result in Unicode characters. Reverse order is a different composite. No gold or pair selection is generated.
- For adversarial documents, use `python scripts/make_adversarial.py --split test ...`; choose the mechanism and source yourself. `--split dev` is the default. Test text, manifest, embeddings, embedding cache and SQLite database are gitignored and blocked by the pre-push guard until the completed valid test run. Never force-add them early. The local test shard is built with `B2_OFFLINE=1 python scripts/build_embeddings.py --split test`; it has a separate text-free index under `corpus/synthetic_test/index/`. The runtime merges its DB only for test/all and searches the corresponding shard. A SHA-256 of each test-synthetic document is included in the LLM request cache identity and transaction cache identity without changing the committed base corpus version. Duplicate-case request reuse remains intentional and requires identical content.
- Before **any dev live run**, complete and locally build the held-out synthetic shard, then run `python scripts/freeze_test_synthetics.py` and commit only `cases/FROZEN-SYNTHETIC.sha256`. It binds the local test database, manifest, document files and index; it contains only the digest, not their content. It cannot be resealed with changed inputs after a dev live run or after `code-frozen`. Live evaluation and `freeze_check.py` verify it alongside the separately committed held-out case hash. Back up the exact local-only files. Never share their content before the permitted release point.
- Run `python scripts/pre_push_guard.py < /dev/null` on POSIX before pushing; use the hook or equivalent empty stdin on Windows. The guard checks outgoing history, not only the current index. The test shard and `db/test_docs.sqlite` (including sidecars), test gold/results/cache and review packets remain protected. The local legacy Chroma folder is ignored and must not be pushed.

## Case schema and metrics

`annotation/README-annotating.md` documents the final case fields. In particular, each gold obligation carries `clause_category`, a deadline and exact `clause_ref`; `deadline_text` is nullable/string, and `conflict_clause_refs` can supply additional exact refs. `duplicate_of` is a same-split adversarial duplicate of identical request content. Composite cases require `constructed: true`, ordered source provenance and, for conflicting class, human-authored E2 plus two distinct exact refs across obligations and conflict refs. Exact source refs are checked at mapped offsets; validation does not determine whether a legal conflict is genuine.

Non-strict `build_cases.py` permits an empty test split for dev work, preserving OpenCode's fix; `--strict` rejects an empty split, and strict validation/freeze enforce 26 dev and 30 test with configured class counts. An empty-test hash from dev-only compilation is a placeholder, **not** a frozen 30-case commitment. The case compiler may require `--replace-commitment` before the first dev live run when real held-out cases replace the placeholder. Never change the commitment after dev live starts.

Per-case CSV and failure digests mark `constructed`. Aggregate metrics separately report constructed-conflicting exception rate and E2-code recall, with numerator/denominator and Wilson intervals; E2-code recall counts an E2 prediction among constructed cases whose human gold contains E2. Overall metrics remain as before. README generation discloses constructed E2 and separately reports those metrics. The observed natural-conflict frequency in this deliberately selected small corpus cannot be generalized.
