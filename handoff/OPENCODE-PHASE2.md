Install the optional pinned encoder with `python -m pip install -r requirements-embedding.txt` and install model weights explicitly. Pin and record the exact adapter/model revision before live runs.

## Safety, tests and later handoffs
- Install and run `scripts/pre_push_guard.py` as a Git pre-push hook. It checks outgoing commit trees and blocks protected gold, cache and test results before a valid frozen live run. Keep the gitignore embargo; after the run, force-add only the release artifacts required for replay. Do not send held-out gold or per-case test results to the build agent before freeze.
- `python run_eval.py --split test` and the CI replay leg intentionally cannot pass before the corpus, human cases, calibration, freeze tags, completed live log and cache exist. `B2_OFFLINE=1` blocks IP sockets in agent-importing processes; it is not a machine-wide firewall for arbitrary subprocesses. The real model, optional sentence-transformers installation, adapter, Windows platform and external CI have not been tested by the build agent.
- A partially resumed live case with no earlier full measurement is excluded from the end-to-end latency denominator. The date parser deliberately escalates unsupported/ambiguous formats. Model-flagged E2 conflicts are cross-checked against candidates and default-escalating types, not legally adjudicated.
- Tuning-round summaries in `eval_results/rounds/` are JSON files whose `run_dir` is relative to `eval_results/` and points to a dev run directory; README tuning metrics are re-derived from that run's `cases.csv`. Started and completed held-out run entries are separate; the README counts started live test runs.
- The review kit runs after the frozen full dev + test replay. `reviews/make_packet.py` produces three randomized blinded packets; `reviews/ingest_verdicts.py` and `reviews/agreement.py` default to the packet manifest's full-run database, or accept `--db`. No reviewer data or verdicts are included in the bundle. Review counts are written to the escalation only on unanimous supplied counts; per-reviewer optional counts remain in structured note JSON.
- Keep all integration changes in `INTEGRATION-LOG.md`. After the valid frozen test result, do not change prompts, code, thresholds, cache or cases; fixes require v1.1 and a re-baseline.
